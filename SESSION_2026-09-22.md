### 4. Saved Designs (consistent re-pricing, no AI variance)
- Problem: re-running AI detection on the same cake photo gives a different element list each time → different price.
- Fix: save the element composition (`element_key` + quantity only, **no price**) as a named "recipe". Reopening it recalculates price fresh from current `design_elements`/`flavors` config — never from a stored price or a new AI run.
- New table `cake_saved_designs` (`migrations/016_cake_saved_designs.sql` — run this).
- New screen: Saved Designs (Home → 📋 Saved Designs) — list, recalculate, delete.
- `ResultScreen.tsx` → **📋 Save Design** button.
- Key files: `src/types.ts`, `src/utils/pricing.ts` (`buildAnalysisFromSavedDesign`), `src/services/SupabaseService.ts`, `src/screens/SavedDesignsScreen.tsx`.

### 5. "Same cake photo?" detection (perceptual hash, option 2)
- Question: if User 2 uploads the same/similar cake photo User 1 already priced, can we reuse User 1's saved design instead of a fresh (variable) AI run?
- Built: dHash (64-bit perceptual hash), computed for both **JPEG and PNG** (pure-JS decoders `jpeg-js` + `pngjs`, no native rebuild needed).
- On analyze, if a new photo's hash is within Hamming distance 10 of a saved design's hash → **confirm dialog** ("Similar Design Found — Use Saved Design / Run New AI Analysis"). Never auto-applied.
- New column `image_phash TEXT` on `cake_saved_designs` (`migrations/017_cake_saved_designs_phash.sql` — run this).
- Key file: `src/utils/imageHash.ts`.
- New deps: `jpeg-js`, `pngjs`, `@types/pngjs`, `buffer` (all pure-JS, no native linking).
